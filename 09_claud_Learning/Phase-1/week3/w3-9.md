## TREE FOUNDATIONS — COVERED W3 D4 (Apr 6)

### TreeNode struct
```cpp
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};
```

### Recursion on trees — 5-step formula
```
1. Base case      → if (root == nullptr) return SOMETHING
2. Go left        → recurse on root->left
3. Go right       → recurse on root->right
4. Combine        → use left and right answers
5. Return         → send answer up
```

### LC #226 — Invert Binary Tree ✅
```cpp
TreeNode* invertTree(TreeNode* root) {
    if (root == nullptr) return nullptr;
    TreeNode* left = invertTree(root->left);
    TreeNode* right = invertTree(root->right);
    root->left = right;
    root->right = left;
    return root;
}
```
**Mistake:** wrote `invertTree(left)` instead of `invertTree(root->left)`

### LC #104 — Max Depth ✅
```cpp
int maxDepth(TreeNode* root) {
    if (root == nullptr) return 0;
    int left = maxDepth(root->left);
    int right = maxDepth(root->right);
    return max(left, right) + 1;
}
```
**Key insight:** base case returns 0 — nullptr is not a node.

### LC #100 — Same Tree ✅
```cpp
bool isSameTree(TreeNode* p, TreeNode* q) {
    if (p == nullptr && q == nullptr) return true;
    else if (p == nullptr || q == nullptr) return false;
    else if (p->val != q->val) return false;
    bool left  = isSameTree(p->left,  q->left);
    bool right = isSameTree(p->right, q->right);
    return left && right;
}
```
**Mistakes:** `p != q` instead of `p->val != q->val`. Null check must come before value access.

### LC #572 — Subtree of Another Tree ✅
```cpp
bool isSubtree(TreeNode* root, TreeNode* subRoot) {
    if (root == nullptr) return false;
    if (root->val == subRoot->val) {
        if (isSameTree(root, subRoot)) return true;
    }
    bool left  = isSubtree(root->left,  subRoot);
    bool right = isSubtree(root->right, subRoot);
    return left || right;
}
```
**Mistakes:** `&&` instead of `||`. isSameTree return not handled correctly at first.

## AUTH FOUNDATIONS — COVERED W3 D5 (Apr 7)

### API Key auth
- Client sends `X-API-Key` header with every request
- Server checks against expected value
- Wrong or missing → 401

### JWT auth
- Client sends username + password to `POST /login`
- Server verifies, generates signed JWT using `python-jose`
- JWT structure: `header.payload.signature`
- `sub` = username, `exp` = expiry (30 min)
- Server calls `jwt.decode()` — no DB lookup needed
- Tampered or expired → `JWTError` → 401

### Key concepts
- 401 = not authenticated
- 403 = not authorized
- API keys: best for devices/services
- JWT: best for users/sessions — stateless, expiry built in

### POST /login — clean version
```python
class UserLogin(BaseModel):
    username: str
    password: str

@app.post("/login")
def login(user: UserLogin):
    if user.username != "admin" or user.password != "1234":
        raise HTTPException(status_code=401, detail="Invalid username or password")
    return {"message": "Login successful", "access_token": create_access_token(user.username)}
```

## HTTP/HTTPS + TLS — COVERED W3 D7 (Apr 9)

```
Client                                    Server
  |--------- 1. Client Hello ----------->|
  |<-------- 2. Server Hello + Cert -----|
  |  [client verifies cert with CA]      |
  |--------- 3. Session Key ------------>|
  |  [server decrypts with private key]  |
  |<======== 4. Encrypted HTTP data ====>|
```
- Asymmetric encryption — used once to exchange session key. Slow.
- Symmetric (AES) — used for all data after handshake. Fast.
- AWS IoT Core uses mTLS — both device AND server present certificates
