## BST — BUILT W7 D4

**Full C++ BST implemented from scratch. 3-file structure: `bst.h`, `bst.cpp`, `main.cpp`.**

Location: `08_repeat/week7/cpp-bst/`

**Node struct:** 3 constructors — default, value-only, full (value + left + right).

**BST class — private helpers + public wrappers pattern:**
- Private helpers take `Node* root` parameter, return `Node*` so parent can relink
- Public wrappers hide root from caller — user just calls `tree.insert(5)`
- Why return `Node*`: recursive calls return updated subtree, parent must save it or change is lost

**Insert:** Navigate left/right. Hit null → return new Node. Parent relinks with `root->left = insert(root->left, val)`.

**Search:** Navigate by BST property. Return true on match, false on null.

**Delete — 3 cases:**
- Leaf (no children) → return nullptr
- One child → return that child
- Two children → find inorder successor (minNode of right subtree) → copy value up → delete successor from right subtree

**minNode helper:** Go left until null. Returns smallest node in subtree.

**Traversals:** All three pass `vector<int>& res` by reference — one shared vector, no merging.
- Inorder: left → root → right → gives sorted output for valid BST
- Preorder: root → left → right
- Postorder: left → right → root

**Height:** Returns max(left, right) + 1. Base case null = 0.

**LCA in BST:** Uses ordering property — no need to search both sides blindly.
- Both p,q < root → go left
- Both p,q > root → go right
- Split (one each side, or one equals root) → root is LCA

**3-file structure:**
- `bst.h` — `#pragma once` + Node struct + BST class declaration
- `bst.cpp` — `#include "bst.h"` + all implementations with `BST::` prefix
- `main.cpp` — `#include "bst.h"` + tests
- Compile: `g++ main.cpp bst.cpp -o bst`

## LCA + CONSTRUCT BT — COVERED W7 D3
*(unchanged)*

**LC #236 — LCA of Binary Tree:**

Key insight: recursion returns signals upward. Every node asks left and right subtrees — did you find p or q?

- Both sides return non-null → this node is the LCA → return root
- Only left returns non-null → answer is in left subtree → return left
- Only right returns non-null → answer is in right subtree → return right
- Both null → neither p nor q here → return nullptr
- Node itself is p or q → return it immediately (don't go deeper)

```cpp
TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
    if (root == nullptr) return nullptr;
    if (root == p || root == q) return root;
    TreeNode* left = lowestCommonAncestor(root->left, p, q);
    TreeNode* right = lowestCommonAncestor(root->right, p, q);
    if (left && right) return root;
    return left ? left : right;
}
```

**LC #105 — Construct BT from Preorder + Inorder:**

Key insights:
- Preorder first element = always the root
- Find root in inorder → everything left = left subtree, everything right = right subtree
- leftSize = rootIndex - inStart → tells you how many preorder elements belong to left subtree
- Use unordered_map for O(1) inorder lookup
- Pass indices, not new vectors — avoids O(n) copying every call

**Index arithmetic rule:** end = start + count - 1. Left preorder ends at preStart + leftSize (not preStart + leftSize + 1).

```cpp
TreeNode* build(vector<int>& pre, vector<int>& in,
                int preStart, int preEnd,
                int inStart, int inEnd,
                unordered_map<int,int>& mp) {
    if (preStart > preEnd || inStart > inEnd) return nullptr;
    TreeNode* root = new TreeNode(pre[preStart]);
    int rootPos = mp[pre[preStart]];
    int leftSize = rootPos - inStart;
    root->left = build(pre, in, preStart+1, preStart+leftSize, inStart, rootPos-1, mp);
    root->right = build(pre, in, preStart+leftSize+1, preEnd, rootPos+1, inEnd, mp);
    return root;
}
```

**Why two traversals:** Preorder alone can't tell you where the left subtree ends and right begins. Inorder gives the boundary via leftSize.

**Port:** A number that tells incoming data which program to deliver to. IP = building address. Port = apartment number. Port 80 = HTTP. Port 443 = HTTPS. Port 5432 = Postgres. Port 22 = SSH.

**Socket:** IP address + port + protocol bound together. A live endpoint. A connection has two sockets — one on each side.

**ss -tulnp:** Shows all listening sockets. `t` = TCP, `u` = UDP, `l` = listening, `n` = numeric, `p` = process name + PID. Prefer over netstat on modern Linux.

**netstat -tulpn:** Same flags, same meaning. Older tool, deprecated. Still seen everywhere in docs.

**lsof -i :PORT:** Shows every process with that port open. Use when "port already in use" error appears — find the PID and kill it.

**nmap localhost:** Port scans your own machine. Shows what's visible from outside. Use before deploying to verify firewall is working. Never run against servers you don't own.

**ufw:** Uncomplicated Firewall. Wrapper around iptables.
- `sudo ufw status` — is firewall on? what rules exist?
- `sudo ufw allow 80` — open port 80
- `sudo ufw deny 5432` — block port 5432
- `sudo ufw enable/disable` — turn on/off

**iptables:** Raw firewall. Three chains: INPUT (incoming), OUTPUT (outgoing), FORWARD (passing through).
- `sudo iptables -L -n` — list all rules numeric
- `sudo iptables -A INPUT -p tcp --dport 5432 -j DROP` — block port 5432 incoming
- DROP = silent discard. REJECT = sends error back. Use DROP in production.

**Docker + firewall:** ufw rules block host-level traffic. Docker internal network bypasses ufw — containers still talk to each other. Blocking 5432 on host stops external DB access but FastAPI → Postgres still works internally.

**Production rule:** Expose only port 80 (nginx). Block 5432, 8000, everything else. Let nginx be the only entry point.

## BST ITERATIVE INORDER — COVERED W7 D1
*(unchanged)*

**BST property:** Every node in the entire left subtree must be less than root. Every node in the entire right subtree must be greater than root. Not just immediate children — entire subtree.

**Inorder traversal of valid BST always gives sorted order.** This is the key insight behind LC #98 and LC #230.

**Iterative inorder skeleton (used for both problems):**
```cpp
TreeNode* curr = root;
stack<TreeNode*> st;
while (curr != nullptr || !st.empty()) {
    while (curr != nullptr) {
        st.push(curr);
        curr = curr->left;
    }
    curr = st.top();
    st.pop();
    // VISIT curr here
    curr = curr->right;
}
```

**LC #98 — iterative:** Pop first → THEN check `prev != nullptr && curr->val <= prev->val` → return false. Update `prev = curr`. Return true after loop.

**LC #230 — iterative:** Track `count`. After pop, decrement count. If count == 0 → return curr->val.

**Key C++ rule:** Always initialize pointers. `TreeNode* prev = nullptr` not `TreeNode* prev`. Uninitialized pointer = garbage value = silent wrong behavior.

## SQL — COVERED W6 D2
*(unchanged)*

**SELECT + FROM + WHERE:** SELECT picks columns. FROM picks table. WHERE filters rows before anything else.

**INNER JOIN:** Only matched rows from both tables. Unmatched rows on either side are excluded.

**LEFT JOIN:** All rows from left table. Unmatched rows on right show as NULL. Put the important table after FROM.

**RIGHT JOIN:** All rows from right table. Unmatched rows on left show as NULL. Rare — most people swap tables and use LEFT JOIN instead.

**GROUP BY:** Collapses rows with same value into one group. Every non-aggregate column in SELECT must appear in GROUP BY. Aggregates: COUNT, SUM, AVG, MAX, MIN.

**HAVING:** Filters groups after grouping. WHERE filters rows before grouping. That is the only difference.

**Subquery:** SELECT inside SELECT. Inner query runs first. Use IN (SELECT ...) to check if a value exists in a list.

**Index:** `CREATE INDEX idx_name ON table(column)`. Speeds up lookups. Seq Scan = no index = slow. Index Scan = index used = fast.

**EXPLAIN ANALYZE:** Put before any query. Shows execution plan — Seq Scan vs Index Scan.

## PAGINATION — COVERED W6 D6
*(unchanged)*

**Offset pagination:** Client sends `page` and `limit`. Server calculates `skip = (page-1) * limit`. DB applies `OFFSET skip LIMIT limit`. Simple to implement. Works well for small/medium datasets. Allows jumping to any page directly.

**Problem at scale:** DB scans and discards all skipped rows internally. Page 1000 with limit 10 = DB processes 10,010 rows to return 10. Also unstable when rows are inserted frequently — rows can shift between pages causing duplicates or gaps.

**Cursor pagination:** Instead of skip, use a marker — last seen `id` or timestamp. Query becomes `WHERE id > last_id LIMIT 10`. DB uses index to jump directly. No scanning. Consistent performance at any depth.

**Tradeoff:** Cursor can't jump to arbitrary pages — forward only. Good for infinite scroll, logs, real-time feeds. Offset is fine for small datasets or when direct page jumping is needed.

**IoT rule:** Device list → offset fine. Second-by-second sensor readings at scale → cursor.

## BACKTRACKING — COVERED W6 D1 + W6 D3 + W6 D5 + W6 D7
*(unchanged)*

**Subsets (LC #78):** Record `curr` BEFORE the loop. Loop from `index`. push → recurse(`i+1`) → pop.

**Permutations (LC #46):** Record only when `curr.size() == nums.size()`. Loop always from 0. `visited[]` tracks used elements.

**Combination Sum (LC #39):** Loop from `ind`. Reuse same element → recurse with `i` not `i+1`. Pass `sum + candidates[i]` inline. Always push → recurse → pop. After saving result, always return immediately.

**Letter Combinations (LC #17):** `ind` = which digit. Loop through letters of that digit. Recurse with `ind+1`. Map key must be `char`.

**Word Search (LC #79):** DFS on grid. Mark visited before recursing, unmark after. Check last char match before going deeper.

**N-Queens (LC #51):** One queen per row. 3 sets for constraints. Place/erase. Base case row == n.

**Palindrome Partitioning (LC #131):** `ind` is cursor. Loop `i` from `ind`. `substr(ind, i-ind+1)`. Base case ind == s.size().

**Sudoku Solver (LC #37):** 3 sets pre-filled. Box index = `(row/3)*3 + col/3`. Try 1-9, check sets, place, recurse, undo. Return bool. Base case row == 9. Constraint check: `&&` not `||` — number must be absent from ALL three sets.

**Key rule — i vs ind in Combination Sum:** Pass `i` to recurse, not `ind`. `i` = stay or go forward. `ind` = always restart from parent's position. Passing `ind` would allow duplicates like [2,3,2].

**BST iterative inorder:** Push left until null. Pop = visit. Go right. Stack holds pending ancestors. Always initialize prev = nullptr. Pop FIRST, then check prev vs curr.

**LCA of Binary Tree:** Every node reports up — found p, found q, or found nothing. Both sides non-null = current node is LCA. One side non-null = pass it up. Both null = return nullptr.

**Construct BT from Preorder+Inorder:** preorder[preStart] = root. Find root in inorder via hashmap. leftSize = rootIndex - inStart. Left preorder = preStart+1 to preStart+leftSize. Right preorder = preStart+leftSize+1 to preEnd. Index rule: end = start + count - 1.

Delete: leaf→nullptr, one child→return child, two children→inorder successor (minNode of right subtree)→copy value→delete successor. ## THINGS I STRUGGLED WITH

*(new entries from W7 D4 appended)*

- **What:** LC #236 — wrote recursive calls but didn't capture return values. **Why:** forgot that in C++ if you don't assign a function's return value, it's thrown away. **Fix:** always assign recursive calls — `TreeNode* left = recurse(...)`. Never call and discard.
- **What:** LC #236 — returned `right` when `left != nullptr` and vice versa. **Why:** muscle memory slip under pressure. **Fix:** say it out loud before writing — "left has the answer, return left."
- **What:** LC #105 — passed unordered_map by value not reference. **Why:** forgot that passing by value copies the entire map on every recursive call. **Fix:** always pass large structures by reference in recursive helpers. Add `&` to map parameter.
- **What:** LC #105 — confused by index arithmetic (preStart + leftSize). **Why:** didn't connect start + count - 1 = end rule. **Fix:** say before writing — "end = start + count - 1. The +1 and -1 cancel."
- **What:** GET /devices — used `Header()` instead of `= None` for optional query param. **Why:** confused HTTP headers with query params. **Fix:** query params = default value in function signature. Headers = `Header()`. They are different things.
- **What:** POST /devices — used status_code=500 for duplicate. **Why:** picked server error instead of client error. **Fix:** 4xx = client did something wrong. 5xx = server broke. Duplicate input = client's fault = 400 or 409.
- **What:** LC #37 — used `||` instead of `&&` in constraint check. **Why:** read it as "if any set has it, skip" instead of "only place if ALL sets don't have it". **Fix:** say before writing — "valid means absent from row AND column AND box. All three. Use &&."
- **What:** LC #37 — forgot to place number on board before recursing. **Why:** inserted into sets but didn't update the board itself. **Fix:** two operations always together — insert into sets AND write to board. Undo both after.
- **What:** CORS middleware — described it as logging middleware. **Why:** confused CORS (cross-origin browser policy) with request logging. **Fix:** CORS = browser security, different origins. Logging = printing request info. Completely different purposes.
- **What:** BST delete two-children case — didn't understand why `root->RightNode = del(root->RightNode, successor->Value)`. **Why:** didn't connect that after copying successor's value up, a duplicate exists in the right subtree that must be deleted. **Fix:** say before writing — "copy value up, then delete the duplicate from where it came from."
