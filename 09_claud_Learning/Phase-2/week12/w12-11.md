**CAP DB names:** CP = MongoDB, HBase, Zookeeper | AP = Cassandra, DynamoDB, CouchDB.

**Message queues key takeaways:**
- Kafka = distributed append-only partitioned commit log. Sequential I/O + OS page cache = insane write speed. Consumer tracks offset, not broker.
- Partition count = parallelism ceiling. Consumers in group ≤ partitions.
- RabbitMQ = smart broker, complex routing, ephemeral messages, push model. Use for: checkout pipelines, RPC, DLQ retry logic.
- Kafka = dumb broker, persistent log, pull model. Use for: clickstream, IoT ingestion, ML training data, event replay.
- Event sourcing = store history of changes, not current state. Replay to reconstruct.
- CQRS = split read and write paths.
- At-least-once = duplicates possible → must be idempotent. Exactly-once = Kafka EOS via idempotent producer + transactional coordinator + 2PC.

**Caching at scale key takeaways:**
- CDN = edge servers serving static assets locally.
- Sentinel = HA failover only. Cluster = horizontal sharding via 16,384 hash slots.
- Invalidation: TTL | Write-through | Cache-aside.
- Thundering herd fix: mutex lock or soft expiry + background refresh.
- Devices API: GET cache-aside soft 55min/hard 60min. POST write-through + invalidate list.

**Ride-sharing HLD key takeaways:**
- Location updates: 250k writes/sec → Redis Cluster (geo index). GEOADD + GEORADIUS.
- Geohashing (S2 geometry) — divide map into cells, match within nearby cells only.
- WebSockets for real-time driver location push to rider. Not HTTP.
- Kafka for ride requests (replay, durability). RabbitMQ for payments + notifications (routing, DLQ).
- PostgreSQL (PostGIS) for relational data. Redis for ephemeral location only.
- Master-replica + Patroni for PostgreSQL HA.
- Driver location Redis key: `driver:location:{driver_id}` → TTL 30s (auto-expires on disconnect).
